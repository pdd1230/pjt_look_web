# LOOK · 손가락 인식 실험실

사진·실시간 웹캠·동영상을 입력받아 손가락 수를 인식하고, 수기로 작성한 정답과 비교하는 로컬 교육용 웹서비스입니다. 첨부 `main-2.py`의 최신 처리 흐름과 판정 모듈을 재사용합니다. **비전 에이전트는 포함하지 않으며 배포하지 않았습니다.**

**시작 순서: ZIP 전체 압축 해제 → setup_windows.bat → MySQL/.env 설정 → start_windows.bat → http://127.0.0.1:8000**

## 1. 포함 기능

| 화면 | 기능 |
|---|---|
| 사진·정답 | 원본 보존·EXIF 방향 적용·수기 정답·확정·수정 이력·사진 분석·재분석 |
| 실시간 웹캠 | 브라우저 카메라 연속 추론·손별/전체 개수·처리 시간·전송 빈도·최근 분석 프레임 평가 캡처 |
| 동영상 | 업로드·모든 프레임 분석·진행률·결과 MP4·프레임 CSV·선택 프레임 평가 |
| 비교·오답 분석 | 검출·분류·손별 비교·절대오차·수기 원인/검토/개선 의견·조건별 건수·CSV |
| 상세 결과 | 관절 21개·골격·개수·판정 이유·측정값·정규화/3D 좌표 CSV |

## 2. Windows 설치

새 폴더에 압축을 풀고, 기존 프로젝트와 별도의 가상환경을 사용하세요. Python **3.11.x 권장**입니다. 현재 실제 검증은 Linux Python 3.12.14에서 수행했으므로 Windows 3.11 설치는 사용자 PC에서 확인해야 합니다.

PowerShell에서 프로젝트 루트로 이동합니다. 아래 경로는 실제 압축 해제 위치로 바꾸세요.

```powershell
cd D:\LSK\LOOK_Web
py -3.11 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pip check
Copy-Item .env.example .env
notepad .env
```

이미 `.env`를 작성했다면 Copy-Item으로 덮어쓰지 마세요. 같은 작업을 돕는 `setup_windows.bat`도 포함되어 있습니다. **원본 환경 전체 대신 루트 requirements.txt만 설치**합니다. `original_project/requirements.txt`는 설치하지 마세요. OpenCV는 `opencv-contrib-python` 하나만 사용합니다. 이 서비스에는 TensorFlow/YOLO를 설치할 필요가 없습니다.

### MySQL 설정

```powershell
sc.exe query MySQL
mysql -u root -p
```

`mysql`을 찾지 못하면 설치 폴더의 mysql.exe 전체 경로로 실행하세요. MySQL에서 다음을 실행합니다.

```sql
CREATE DATABASE IF NOT EXISTS look_web_db CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

기존 MySQL 계정을 사용하거나, `scripts/create_database.sql`의 예시 비밀번호를 먼저 바꾸고 전용 계정을 생성하세요. `.env`에는 실제 계정을 적습니다.

```dotenv
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=look_web_db
DB_USER=look_user
DB_PASSWORD=직접_정한_비밀번호
```

비밀번호에 `#` 등이 있으면 `.env`에서 따옴표로 감싸세요. URL 객체로 접속 정보를 구성하므로 비밀번호를 URL 인코딩하지 않아도 됩니다. 테이블 6개는 최초 실행 때 자동 생성합니다. **MySQL 연결 실패 시 다른 DB로 자동 전환하지 않습니다.**

### 검사와 실행

```powershell
.\.venv\Scripts\python.exe scripts\check_environment.py
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --workers 1
```

http://127.0.0.1:8000 에 접속합니다. 종료는 `Ctrl+C`입니다. 다음부터는 `start_windows.bat`으로 실행해도 됩니다. `/docs`에서는 FastAPI API 명세를 확인할 수 있습니다.

- 영상 작업과 웹캠 세션의 메모리 상태 때문에 **worker는 1개**로 실행합니다.
- `--reload`는 실행 중 영상/카메라를 끊으므로 수업 운영에는 사용하지 마세요.
- 재시작 시 진행 중 작업은 FAILED로 표시합니다. 다시 분석하면 새 실행으로 기록합니다.
- 로그인은 이번 범위에 없습니다. 기본 실행은 같은 PC에서만 접속하는 127.0.0.1입니다.

## 3. 사진·정답 사용법

1. **사진·정답 → 사진 등록**에서 사진을 등록합니다.
2. 원본을 확인하며 실제 손 개수·전체 손가락 수·손별 수·조명·촬영 조건·가림·비고·작성자를 입력합니다.
3. 상태를 **확정**으로 저장합니다. 분석은 정답 작성 전에도 가능하지만 평가는 대기입니다.
4. **사진 분석하기**를 누르고 예측을 확인합니다. 정답 작성 화면에서는 예측을 기본적으로 접어 둡니다.
5. 비교·오답 분석 화면에서 평가와 원인을 검토합니다.

| 실제 상태 | 실제 손 개수 | 실제 손가락 수 | 손별 개수 예 |
|---|---:|---:|---|
| 손 없음 | 0 | 빈칸 | 빈칸 |
| 주먹 | 1 | 0 | 0 |
| 한 손 | 1 | 3 | 3 |
| 양손 | 2 | 5 | 화면 왼쪽 2, 오른쪽 3 → `2,3` |

- 등록 시 빈 정답 v1을 생성하고 수기 저장마다 v2, v3…로 보존합니다. 예측을 정답란에 자동 복사하지 않습니다.
- 판정 불가에는 비고 사유가 필요합니다. 작성 중·판정 불가는 정확도 분모에서 제외합니다.
- 최대 20MB·3천만 픽셀. 3023×4032 사진도 입력 가능하며 EXIF 방향 적용 후 최대 960×1280 안으로 비율을 유지해 축소합니다.
- 원본은 덮어쓰지 않습니다. 화면 미리보기는 방향 적용 분석본이며 별도 원본 내려받기를 제공합니다.

## 4. 실시간 웹캠

1. **카메라 시작**을 누르고 카메라 권한을 허용합니다. localhost에서 사용하세요.
2. 원본·분석 결과·손별/전체 수·처리 시간·왕복 시간·실제 분석 빈도를 확인합니다.
3. **최근 분석 프레임을 평가용으로 저장**하면 같은 순간의 원본·예측·결과 사진을 연결합니다.
4. 사진·정답 탭의 캡처를 선택해 수기 정답을 작성합니다.
5. 끝나면 **정지**합니다.

좌우 반전은 적용하지 않습니다. 수기 정답도 화면 왼쪽부터 작성합니다. 일반 프레임은 영구 저장하지 않으며 최근 프레임 하나만 메모리에 유지합니다. 선택 캡처와 세션 요약을 저장합니다.

한 번에 요청 하나만 보내 대기 프레임이 누적되지 않습니다. 약 4회/초를 목표로 하지만 장비에 따라 느려집니다. 최대 2개 세션입니다. 끊긴 세션은 다음 세션 생성 시 120초 유휴 기준으로 정리합니다.

원본 7프레임/4회 우세 안정화 기준을 유지하므로 웹 전송 4회/초에서는 기존 30fps 콘솔보다 상태 반영이 늦을 수 있습니다. 임계값을 임의로 재튜닝하지 않았습니다. 다른 PC에서 HTTP 접속하면 카메라가 제한될 수 있으므로 같은 PC에서 먼저 확인하세요.

## 5. 동영상

1. 영상을 등록하고 **전체 프레임 분석**을 누릅니다.
2. 상태·진행률을 확인하고 완료 후 결과 영상과 프레임 예측 CSV를 받습니다.
3. **0부터 시작하는 프레임 번호**를 입력해 평가할 원본 프레임을 추출합니다.
4. 완료된 영상 분석의 해당 예측을 연결하며 사진·정답 탭에서 정답을 작성합니다.

최대 250MB·5분·240fps, 동시 영상 작업 1개입니다. 읽을 수 있는 모든 프레임을 순서대로 분석합니다. 프레임별 관절·3D 좌표·진단도 DB에 기록하므로 DB 크기가 증가합니다. 디코딩이 중간에 끊기면 실패로 표시하고 부분 영상을 완성 결과로 제공하지 않습니다. 원본 음성은 제외합니다. CSV는 OpenCV가 제공한 프레임 시각을 우선 사용하며 제공되지 않으면 프레임/FPS로 계산하고 대체 횟수를 작업 정보에 기록합니다. 결과 MP4는 일정 FPS로 쓰므로 가변 FPS 원본에서는 개별 프레임의 재생 시점이 달라질 수 있습니다. 정확한 시간 대응 실험은 일정 FPS 영상으로 진행하세요.

출력은 OpenCV mp4v입니다. 브라우저에서 재생되지 않으면 **내려받아 VLC 등의 플레이어로 확인**하세요. Windows 코덱·디코더·인코더는 실제 PC에서 확인해야 합니다.

영상 분석 전에 추출했다면 연결할 영상 예측이 아직 없으므로 사진 분석을 실행하거나 영상 분석 완료 후 다시 추출하세요. 영상 캡처에서 사진 분석을 실행하면 IMAGE 모드의 별도 실행이 생성됩니다. 선택 프레임의 평가를 전체 영상 정확도로 표현하지 않습니다.

## 6. 평가·CSV

- 검출: 실제·예측 손 개수가 같은지 비교합니다. 박스 위치 정확도는 아닙니다.
- 전체 분류: 실제 손이 있는 확정 입력에서 손 개수와 손가락 합계가 일치해야 성공입니다. 미검출도 실패에 포함합니다.
- NO_HAND는 손가락 수 NULL/CSV 빈칸입니다. 주먹 0과 구분하며 미검출 숫자 오차도 빈칸입니다.
- 손별 정답이 있으면 화면 왼쪽부터 대응해 손별 절대오차 합계를 계산합니다. `[2,3]` 대 `[3,2]`는 합계 일치·손별 불일치·오차합 2입니다.
- 손별 일치율은 손 개수가 같아 대응 가능한 수기 정답의 **개별 손**을 분모로 합니다. 대응 불가능한 미검출은 전체 분류 실패에 포함하고 손별 분모에서는 제외합니다.
- 손 없는 정답에는 분류 성공을 비우고 검출만 평가합니다. 모델/분석 실패 ERROR는 NO_HAND와 구분합니다.
- 최신 정답·최신 분석을 기본 집계하며 전체 이력도 선택할 수 있습니다. 수기 검토는 평가 조합별로 저장합니다.

수기 정답 이력 CSV, 전체 예측 CSV, 기존 test_cases.csv의 10개 열을 유지한 확장표, 오답 CSV, 평가 전체 이력 CSV를 제공합니다. UTF-8 BOM으로 한글을 내보냅니다. 수기 입력이 `= + - @`로 시작하면 엑셀 수식 실행 방지를 위해 작은따옴표를 붙입니다.

기존 data/ground_truth.csv·data/test_cases.csv·original_project/output/evaluation.csv는 **과거 기록**입니다. 대응 원본 사진 전체가 없어 신규 DB 측정값으로 자동 등록하지 않습니다.

## 8. 검증·장애 조치

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.\.venv\Scripts\python.exe -m pytest tests -q
```

테스트는 전용 임시 SQLite를 사용하며 사용자 MySQL 데이터를 수정하지 않습니다. 실제 검증 결과와 미확인 범위는 **docs/VALIDATION.md**에서 확인하세요. 목표 정확도 80%·웹캠 3~5회/초는 달성치가 아닙니다.

| 현상 | 확인 |
|---|---|
| MySQL 연결 실패 | 서비스 RUNNING, DB 이름·계정·비밀번호·3306. DATABASE_URL이 활성화되면 DB_*보다 우선합니다. |
| 모델 없음 | ZIP 전체 해제, models/hand_landmarker.task 존재. 검사 스크립트로 실제 로딩 확인 |
| 모듈 없음 | IDE가 이 폴더 .venv를 사용하는지 확인하고 동일 Python으로 pip 설치 |
| 카메라 안 열림 | localhost·권한·다른 카메라 사용 프로그램 종료 |
| 숫자 변경 지연 | 원본 안정화와 실제 분석 빈도 확인 |
| 결과 MP4 재생 불가 | 다운로드 후 플레이어에서 확인 |
| 포트 사용 중 | 기존 서버 종료 또는 --port 8001 지정 |

storage 파일과 DB를 함께 백업해야 결과 링크를 복원할 수 있습니다. 독립 사진 60장·손 없는 사진 10장·양손·실제 손 영상 2개·웹캠 5분 검증을 사용자 PC에서 수행하세요. 측면·가림·겹침·손 교차 시 좌우 슬롯 변경 등 원본 알고리즘의 한계가 남습니다.
