## 1. 결론 및 계획 변경 사유

첨부된 원안 「실무형 컴퓨터 비전 프로젝트 추천 10선」은 추적 ID, 복합 기능, 미세조정, 데이터베이스, GUI 등을 포함합니다. 후속 8주 계획은 예제의 일부 수정이 가능한 학생을 가정했으므로, **복사·실행 수준인 학생 3개 조가 5주 동안 독립적으로 완성하기엔 위험**합니다.

### 이번 교육의 성공 기준

- **반드시:** 입력 사진/동영상 읽기 → 기존 모델 또는 컴퓨터 비전 알고리즘 실행 → 결과를 화면에 표시 → 결과 파일 1종 이상 저장 → 간단한 테스트 → 발표.
- **권장:** 이미지 20~30장 또는 30~60초 영상 2~3개로 시험하고 수작업 정답과 비교.
- **제외:** 새로운 모델 학습, 대량 라벨링, 사람 ID 추적/재식별, 웹서버·DB·회원 로그인, 실시간 CCTV 연결, 고성능 GPU 전제, 복잡한 PyQt 앱.
- **발표 조건:** AI가 생성한 코드라도 입력·출력과 주요 함수 2~3개를 자기 말로 설명하고 간단한 수치를 변경할 수 있어야 함.
- **중요한 표현:** 사전 학습 모델을 실행한 프로젝트는 'AI 모델 활용'이지 '우리가 AI 모델을 새로 개발/학습'한 것이 아닙니다.

## 3. 3개 조에 실제 배정할 프로젝트(최우선 추천)

### 1조: 영상 속 사람 수 분석기

- **입력:** MOT17의 허가된 일부 학습 영상 또는 짧은 사람 등장 영상(30~60초). 기존 MOT17 실습 코드를 활용할 수 있음.
- **기본 절차:** 동영상 파일 읽기 → YOLO 사전 학습 모델로 `person` 탐지 → 박스와 프레임별 인원수 표시 → `frame_index,count` 형식으로 CSV 저장.
- **최소 완료 조건:** 정상 실행되는 영상 2개, 결과 CSV 2개, 직접 확인한 20프레임과 AI 인원수 비교표.
- **금지:** '출입/퇴장 수'라고 발표하지 않기(그건 추적과 방향 판단이 필요). **화면에 동시에 보이는 사람 수**만 측정.
- **선택 과제:** 인원수 그래프 1개, confidence 임계값 변경 비교.
- **주요 위험:** CPU 추론이 느리면 모든 프레임 대신 N번째 프레임만 분석하고 '샘플링된 프레임'이라고 표시.

### 2조: 교실 물품 찾기

- **입력:** 가방·노트북·물병·휴대전화 중 하나 이상이 보이는 사진 20~30장(동의받아 직접 촬영하거나 이용 허용 사진 사용).
- **기본 절차:** 사진 파일 열기 → YOLO로 지원 클래스(예: `backpack`, `laptop`, `bottle`, `cell phone`) 검출 → 박스·이름 표시 → 결과 이미지를 별도 폴더에 저장.
- **최소 완료 조건:** 최소 20장 사진을 실행하고, 탐지한 물체 수를 표로 정리, 성공 및 실패 사례 각각 3개 설명.
- **금지:** 사진에서 물건의 소유자·실제 분실 여부를 확인할 수 있다고 주장하지 않기. 이는 **물품의 종류와 위치를 표시하는 탐지 프로그램**.
- **선택 과제:** 사용자에게 찾을 물품 종류를 입력받아 해당 박스만 강조, CSV로 물품 목록 저장.
- **주요 위험:** 작은 물체와 가림이 있는 사진에서 인식이 누락될 수 있으므로 물품이 잘 보이는 통제된 사진으로 시작.

### 3조: 얼굴 자동 모자이크

- **입력:** 동의받은 정면 얼굴 사진 20장 및 짧은 영상 1개(선택).
- **기본 절차:** OpenCV 내장 Haar Cascade 등 기존 얼굴 검출기 실행 → 얼굴 좌표 추출 → 해당 부분에 모자이크 또는 블러 → 처리 이미지 저장.
- **최소 완료 조건:** 사진 20장 처리, 원본/결과 쌍 제시, 실제 얼굴 수와 검출 수를 사람이 확인한 기록.
- **금지:** 처리 결과가 완전한 개인정보 비식별화라고 주장하거나 검수 없이 외부 공개하지 않기.
- **선택 과제:** 입력 영상 30초를 처리해 새로운 영상 파일로 저장.
- **주요 위험:** 정면·충분한 크기의 얼굴에서 먼저 성공시키고 측면·작은 얼굴 문제는 한계로 보고.

### 조별 과제의 균형

조별 모델 복잡도가 동일하지 않아도 **최소 완료 기능 2개 + 테스트 + 오류 분석 + 발표**를 동일하게 요구하여 공정성을 높입니다. 주제 차이보다 결과의 완성도와 이해도를 중시합니다.

## 7. 사전 준비 사항

1. 조별 샘플 사진 20장 또는 짧은 영상 2개를 **프로젝트 시작 전에** 제공하고 사용권·촬영 동의를 확인.
2. PC 1대에서 먼저 각 프로젝트의 기본 예제를 검증하고 Windows용 설치 명령 및 실행 스크립트를 준비.
3. YOLO 팀은 동일한 사전 학습 경량 모델(예: 기존 실습에 사용한 `yolo11n.pt`)을 공유. 해당 모델에 없는 클래스는 목표에서 제외.
4. 학생에게 새로운 TensorFlow·MediaPipe 등 복잡한 의존성을 임의로 설치하지 않게 함. 특히 09·10 선택 시 별도의 사전 검증된 가상환경 준비.
5. 영상처리 결과는 기본적으로 원본과 다른 파일명으로 저장하도록 제공 코드를 구성.
6. 2주차에서 모델·라이브러리 실행이 어려운 조는 복잡한 기능을 삭제해 입력→처리→저장 기본 흐름만 완성.

- **허용:** ChatGPT 등에 코드 초안 생성, 오류 로그 분석, 함수 설명, 코드 개선을 요청.
- **필수 검증:** 코드가 실행된 실제 PC의 Python·패키지 버전, 사용 데이터와 출력 파일을 직접 확인.
- **개인별 이해 확인:** 학생마다 자신의 담당 코드 10~20줄 또는 함수 하나를 설명하고, 최소 한 군데 변경 후 재실행.
- **제출:** AI에 요청한 대표 프롬프트 2~3개, 받은 코드에서 실제로 수정한 부분, 발견한 오류와 해결 기록.
- **불필요:** GPT가 전체 프로젝트를 대신 만들고 학생들이 이해하지 않은 채 발표하는 방식.

## 9. 장비와 환경 위험

- **웹캠은 필수 아님.** 이미지 폴더 및 녹화 영상으로 모든 기본 목표 충족 가능. 웹캠은 팀의 여유가 있을 때만 구매.
- CPU만으로 모델을 실행하도록 경량 모델을 선택하고 이미지 수·영상 길이 및 분석 프레임 수를 제한. 실제 처리 속도는 PC 사양에 따라 다름.
- 전통적인 Haar Cascade 얼굴 검출은 구현은 간단하지만 측면 얼굴·작은 얼굴 누락 가능성이 큼. 얼굴 전체의 비식별화를 보장하지 않음.
- MOT17은 일부 영상의 라이선스/배포 조건을 확인하고 공식 `train` 파일과 수업용 일부 프레임을 사용. 프레임별 사람 수는 사람의 입장·퇴장 수가 아님.
- 앞서 사용하던 TensorFlow·MediaPipe·NumPy 버전 충돌 환경에 YOLO까지 무조건 추가하지 말고 **프로젝트별 분리 가상환경**을 권장.

## 10. 최종 결론

**5주·복사 실행 수준·3개 조** 조건에서는 아래 배정을 최우선 권장합니다.

- 1조: **AI 영상 속 사람 수 분석기**(MOT17 / YOLO)
- 2조: **교실 물품 탐지 및 찾기**(교내 물품 사진 / YOLO)
- 3조: **얼굴 자동 모자이크**(사용 허가 얼굴 사진 / OpenCV 얼굴 검출)

성공의 기준은 **화려한 대시보드나 높은 정확도보다, 5주 안에 정상 실행되는 프로그램·테스트 결과·학생의 설명 능력을 확보하는 것**입니다.
